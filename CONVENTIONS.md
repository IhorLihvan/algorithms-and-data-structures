# Домовленості для авторів розділів

Щоб розділи різних авторів працювали разом в одній книзі (`main.typ`), пропонуємо однакові правила. Усі функції лежать у [common.typ](common.typ).

## Підключення

На початку розділу:

```typst
#import "common.typ": *
```

Свої визначення `sidenote` і `marginnote` у розділі більше не потрібні.

## Операції (вимога викладача)

Загальнотеоретичні операції пишемо великими літерами, без аргументу-таблиці:

```typst
#op("INSERT", $x$)   // INSERT(x)
#op("SEARCH", $k$)   // SEARCH(k)
#op("DELETE", $k$)   // DELETE(k)
#op("CLEAR")         // CLEAR()
```

Складені назви пишемо через дефіс: `IS-EMPTY`, `EXTRACT-MIN`, `DECREASE-KEY`.

Аргументи: $x$ --- запис, $k$ --- ключ. `INSERT` отримує запис, `SEARCH` і `DELETE` --- ключ, і так само в псевдокоді (`DIRECT-ADDRESS-DELETE(k)`, `HASH-INSERT(x)`). Запис із ключем $k$ і тілом $v$ пишемо $chevron.l k, v chevron.r$.

## Позначення

- $n$ --- кількість записів, $m$ --- кількість комірок, $alpha = n / m$ --- коефіцієнт заповнення (як у Кормена). Позначення Костіва $l f$ і $N$ згадуємо лише в примітці.
- Розмір універсуму ключів --- $|U|$, а не $m$.

## Література

Список один на всю книгу: [references.bib](references.bib). Посилання робимо як у книжках, номером, а не приміткою:

```typst
До половини часу роботи транслятора @kostiv[с. 30] йде на ...
Перші три операції називають @clrs[ч. III] словниковими.
```

Нові джерела додаємо в `references.bib`, а не в текст розділу.

## Мітки розділів

На мітки посилаємося через `@мітка`, а не пишемо номер руками. Тоді номери розділів, рисунків і таблиць оновлюються автоматично в об'єднаному тексті.

| Розділ | Мітка |
|---|---|
| Швидке сортування | `<ch-quicksort>` |
| Сортування злиттям | `<ch-mergesort>` |
| Нормальний алгоритм Маркова | `<ch-markov>` |
| Множина | `<ch-set>` |
| Графи (розділ 4) | `<ch-four>` (уже є) |
| AVL-дерева | `<sec-avl>` |
| Алгоритм Дейкстри | `<sec-dijkstra>` (уже є) |
| Таблиця | `<ch-table>` |
| Хеш-таблиця | `<ch-hash>` |

Рисунки: `<fig-...>`, таблиці: `<tab-...>`, підрозділи: `<sec-...>`.

Якщо розділ колеги ще не злито в книгу, використовуйте `chref`. Він підставить номер, коли мітка з'явиться, а до того виведе запасний текст:

```typst
#chref(<ch-quicksort>)[розділ про сортування]
```

## Алфавітний покажчик

Терміни для покажчика позначаємо через `idx` одразу після першої появи терміна. У тексті позначка нічого не виводить:

```typst
*Хеш-функція*#idx("хеш-функція") --- це ...
#idx("хеш-функція", "метод ділення")   // підтермін
```

Терміни пишемо з малої літери (крім власних назв) і в називному відмінку.

## Код C++

- Код лежить у папці `code/` у звичайних файлах `.h` і `.cpp`, які компілюються і тестуються. У книзі його показуємо через `#code-file("code/table.cpp", part: "search")`, а не копіюємо в текст. Фрагмент у файлі позначаємо рядком `// == search ==`. Так код у книзі завжди збігається з перевіреним.
- Результат програми зберігаємо в `code/output/*.txt` і показуємо через `#program-output(...)`.
- Оформлення за [Google C++ Style Guide](https://google.github.io/styleguide/cppguide.html): типи й функції `CamelCase` (`AddRow`, `IsEmpty`), змінні `snake_case`, закриті поля з підкресленням у кінці (`head_`), константи `kName`, відступ 2 пробіли.
- Кінець рядка: `std::endl`, а не `'\n'`.
- Функції не пишемо в один рядок.
- Результат роботи програми даємо текстом, а не скріншотом.
